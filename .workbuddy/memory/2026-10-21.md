# 2026-10-21 — 选中红框改为"引擎层绘制"(方案B)

## 背景
上一轮"点击签章显示红框"用前端 DOM 覆盖层 `#sealSelectionBox` 实现。用户要求把功能封装在底层，
前端只负责数据传输/编排/事件触发，故改为**方案B：选中框由 Rust 渲染层画进 canvas 像素**，
彻底去掉 DOM 覆盖层。

## 实现（引擎层拥有全部逻辑）
- **状态**：`DocState` 新增 `selected_seal: Option<usize>`（存印章 id）；
  `DocState::default` / `DocumentEngine::load_file` 构造处初始化 `None`。
- **命中+选中**（engine.rs）：
  - 抽出 `compute_seal_hit(page, canvas_w, canvas_h, x, y) -> Option<(index, scale_x, scale_y)>`。
  - `hit_test_seal`（只查询，不改状态）改为复用它。
  - 新增 `select_seal_at(...) -> Option<String>`：命中则 `selected_seal=Some(id)` 并返回 JSON；未命中清空。
  - 新增 `clear_seal_selection()`；`delete_note` 删除的正是选中章时清空。
- **渲染**（render.rs）：
  - 新增自由函数 `draw_selection_rect(ctx,x,y,w,h)`：`save()`→`stroke_style "#FF0000"`→`line_width 2.0`→`stroke_rect`→`restore()`（空心直角实线）。
  - PDF `render_page_to_canvas`：印章叠加之后，若 `doc_state.selected_seal == seal.id` 且同页，
    按 `bmp_w/pdf_pw` 比例换算后画红框（在 putImageData 之后的像素层）。
  - OFD `render_ofd_canvas`：印章叠加之后，用与 `render_seal_ofd` 相同的坐标映射画红框。
- **wasm 导出**（lib.rs）：`select_seal_at(page,canvas_w,canvas_h,x,y)`（内部调用后 `refresh_render()` 重绘）、
  `clear_seal_selection()`（清空+重绘）。
- **桥接**（js/ofd_plugin.js）：新增 `SelectSealAt` / `ClearSealSelection` 并加入导出对象。
- **前端**（index.html）：
  - 删除 `#sealSelectionBox` 的 CSS、DOM 节点、`showSealSelectionBox`/`hideSealSelectionBox`。
  - 左键 click：命中 canvas 页就 `plugin.SelectSealAt(pageIdx, rect.width, rect.height, clickX, clickY)`；
    点空白/工具栏 `plugin.ClearSealSelection()`。
  - 右键 contextmenu：命中已有签章时也先 `SelectSealAt`（引擎画框）再弹菜单。
  - 前端只传 canvas CSS 尺寸 + 点击坐标，命中/选中/绘制全在引擎。

## 关键约定
- 选中框是"画布像素"，不是文档内容，保存/导出不会写入 PDF/OFD。
- `refresh_render()` 在每次选中变化时重绘全部页；canvas 按 `__pg_<container>_p<page>` id 复用，
  重绘后同一元素像素更新（故可在同一 canvas 上读 getImageData 验证）。
- 若后续要多选/拖动/缩放手柄，可在 `selected_seal` 基础上扩展（如 `selected_seals: Vec<usize>`）。

## 2026-10-21 — 文本搜索 UI 下沉到 Rust 层（查找弹框 + 全部标记/上一个/下一个）

### 需求
前端只有一个"查询"按钮；点击后由 **Rust 层**打开查找弹框（输入框 + 全部标记/上一个/下一个），
命中标记、翻页、滚动都由引擎完成。前端只做事件触发与数据传递。

### 实现
- **新模块 `src/search_ui.rs`**：用 web-sys 在 Rust 里构建弹框 DOM（`set_inner_html` 一段内联样式 markup），
  `document.createElement('div')` + `appendChild`；用 `Closure` 绑定 全部标记/上一个/下一个/关闭/回车(Enter=下一个)；
  `thread_local! { KEEP: Vec<Closure<dyn FnMut()>>, KEY: Option<Closure<dyn FnMut(KeyboardEvent)>> }` 保活，
  下次打开前清理旧闭包。状态栏显示"第 X / N 处（第 P 页）"或"未找到"。
- **`lib.rs`**：`mod search_ui;`；导出 `show_search_dialog()`；`pub(crate)` 编排函数
  `search_run(query, show_all)`、`search_step(forward, query)`、`search_clear()`、`scroll_to_page_element(page)`；
  每次搜索后 `refresh_render()` 并滚动到当前命中页（`#__pg_screen_p<page>` 上 scroll_into_view）。
- **`types.rs`**：新增 `SearchMatchRect{page_index,x,y,w,h}`；`DocState` 加
  `search_query / search_matches / search_current / search_show_all`。
  ⚠️ 坑：新增结构体必须放在 `#[derive(Debug,Clone)]` 与 `pub struct DocState` 之间 **之前**，
  否则 derive 会错位挂到新结构体上（E0119 conflicting Clone/Debug + DocState 丢失 Clone）。
- **`engine.rs`**：
  - `search_compute(query)`：PDF 用 **PDFium 文本搜索**取精确矩形（`PdfPageText::search` → `find_next` →
    `segment.bounds()`，注意 `y_top = page_h - rect.top()`）；OFD 按文本项位置估算（`x=item.x+i*font_size`,
    `y=item.y-font_size`）。优先用 `original_data`，搜不到回退 `raw_data`。
  - `search_show_all / search_next / search_prev / clear_search`（next/prev 环形）。
- **`render.rs`**：新增 `pub(crate) find_pdf_text_rects(raw, query)`（PDFium 搜索，返回页面坐标矩形）；
  渲染时按状态画命中标记：全部=黄 `rgba(255,235,0,.35)`、当前=橙 `rgba(255,150,0,.45)`+橙边框；
  PDF 画在 putImageData 之后的像素层，OFD 画在 `ctx.scale` 缩放内(mm 坐标)。
- **`Cargo.toml`**：web-sys 增加 `KeyboardEvent` feature。
- **`js/ofd_plugin.js`**：新增 `ShowSearchDialog`。
- **`index.html`**：移除之前行内搜索框/结果面板/doSearch/bindSearchUI；doc-header 只留一个
  `.query-btn`「查询」按钮 → `onclick=OFD_Plugin.ShowSearchDialog()`。

## 2026-10-21 晚 — 修复查找的两个 bug（整词框选 / 关闭清除）

### bug1: 查"甲方"只框住"甲"，下一个只框"方"，总数 72
- 根因：PDFium `PdfPageTextSearch::find_next()` 返回的是**一处命中的 `PdfPageTextSegments`**，
  其中可能包含**多个矩形**（"甲""方"因分属不同文本段而各占一个 rect）。旧代码把每个 rect 当成一次独立命中，
  导致一处"甲方"变成 2 条（36 处 × 2 = 72），翻页只高亮其中一个字。
- 修复：
  - `SearchMatchRect` 增加 `hit: u32`（逻辑命中序号）；`DocState` 增加 `search_hit_count: usize`。
  - `render.rs::find_pdf_text_hits()`（原 `find_pdf_text_rects`）改为按命中分组返回
    `Vec<(page_index, Vec<(x,y,w,h)>)>`：一次 `find_next()` 的多个 segment 合并为同一 hit 的多个矩形。
  - `engine::search_compute` 为每个 hit 分配序号并展平到 `search_matches`；OFD 每处命中 1 个 hit。
  - `search_next/prev` 按 `search_hit_count` 环移，页码取该 hit 的第一个矩形所在页；
    渲染时同一 `hit` 的所有矩形一起高亮（`is_current = search_current == Some(m.hit as usize)`）。
  - `search_compute` 返回 `search_hit_count`（不是矩形数）。
- 实测：`甲方` 由 72 处 → **36 处**；当前命中框 `w=23px`（≈2 汉字宽），整词框选正确。

### bug2: 关闭查找弹框后命中标记不消失
- 根因：关闭仅移除 DOM，未清引擎搜索状态，canvas 上标记仍在。
- 修复：`search_ui.rs` 关闭闭包里调用 `crate::search_clear()`（清状态 + `refresh_render`）再移除弹框。
- 实测：关闭后高亮像素 **1389 → 0**，弹框移除。

### 关键点
- **PDFium 搜索结果 ≠ 命中数**：一个 hit 可含多矩形，计数/翻页必须按 hit 分组，不能按 rect。
- 类似"按段落拆分"的文字（如不同字体 run 相邻）都会触发该问题，通用修复已覆盖。
