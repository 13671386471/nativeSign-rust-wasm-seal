# 2026-10-16

## 功能实现状态对照表 (对比原 C++/Qt 引擎)
- 产出文档: `docs/feature-status.md` — 全量阅读 `src/*.rs` 后梳理的"已真实实现 vs 未实现/MOCK"对照。
- **已真实实现(可验真)**: SM3/SM2/SM4 (libsm)、SHA256/MD5; PDF 渲染(pdfium-render)、OFD 渲染(Canvas2D)、中文字体(font_provider/font_embed); OFD 解析(ofd_parser 真实 ZIP+XML)、PDF 已有签章/证书解析(engine.rs+x509-parser); PDF/OFD 签章嵌入(含合法 ByteRange / GB/T 33190 Sign_N 结构); SES/PKCS#7 的 DER 编码(der.rs/ses.rs/pkcs7.rs)。
- **仍是 MOCK(不可验真)**: 证书/密钥(crypto.rs MOCK_*_CERT、sm2 随机密钥)、RSA 签名(crypto.rs:234 假)、云签服务(sign.rs:278 假响应)、UKey 硬件代理(ukey.rs 全假)、手机盾(无模块)。
- **明确 stub**: search_text/show_dialog/http_*/can_undo/redo/open_file_back/get_next_note、DCS 格式转换后端、TSA/LTV、PDF 页数文本扫描(engine.rs:72 脆弱)、OFD 渲染保真度(CSS 字体栈非内嵌字体)、签名时间硬编码(ses.rs:493)。
- 核心结论: Rust 版是"渲染+落章+国密结构"可验证原型, 但凡需监管认可的签名必须先补信任链(REPLACE_WITH_REAL_CERT/SIGN_SERVICE/UKEY_PROXY)。

## 未实现功能的 Rust/WASM 可行性分析
- 产出文档: `docs/feasibility-analysis.md` — 逐项分析 16 个未实现/MOCK 功能的 Rust 阻塞点与可行性。
- **核心结论: Rust/WASM 层面零阻塞**。Cargo.toml 的 web-sys 已启用 WebSocket/Request/Response/HtmlInputElement/Crypto/Blob/Url, wasm-bindgen-futures 已就位; 所有 stub 均为纯占位。
- 真正 gate 只有两类: (1) 外部信任/集成基础设施(CA私钥、云签/UKey/手机盾/TSA/DCS 服务端); (2) 少量工程量(OFD 高保真渲染、完整 PDF↔OFD 转换)。
- 关键: WebCrypto 不支持国密(SM2/SM3/SM4), 故国密必须留在 Rust(libsm 已实现), 这反证选型正确。
- 极高/高可行性且无需新依赖: 真实证书(数据替换)、云签(fetch)、RSA 真签名(加 rsa crate)、文本搜索、文件对话框、HTTP 上传、撤销重做、大纲、PDF 页数改用 lopdf、签名时间 JS 注入。
- 受外部约束: UKey(需本机代理+私有协议)、手机盾(后端)、DCS 转换(建议后端化, 客户端只是 HTTP 调用)、TSA(RFC3161+端点)、OFD 保真(fontdue/ab_glyph 纯 Rust 光栅)。
